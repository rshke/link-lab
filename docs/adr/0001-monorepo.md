# 采用 monorepo 管理智能实验室平台

状态：采用。日期：2026-10-15。

前端、Agent、确定性执行和设备模拟器需要共同演进实验规格、设备能力与事件契约。现阶段将它们放在同一仓库，便于在同一次变更中审阅契约、实现及集成测试。

仓库按 `apps/`、`services/`、`adapters/`、`simulators/` 和 `contracts/` 划分职责。源码同仓不赋予跨服务导入或跨服务数据访问权限。各组件独立维护依赖、构建、配置和迁移，后续可以独立发布。

首期以清晰模块边界为主，平台 API 中聚合规格和验证，工作流 Worker 中聚合排程和执行。网关及孪生投影可以与平台同宿主运行。这个目录划分为后续独立部署保留位置，不要求立即引入全部进程、Kubernetes 或复杂任务编排工具。

当前不预设 Python、.NET 或 Node.js 为统一后端技术栈，也不以空的工作区清单绑定包管理器。正式前端位于 `apps/console/`；既有 `device-twin-demo/` 保持原位，仍是可独立运行的界面原型。正式迁移时单独验证资源路径、构建配置及托管关联。

代价是必须持续约束共享代码和数据访问。新增公共库需要已有的实际复用需求，新增服务需要说明数据所有权及对外契约。根目录测试覆盖跨组件边界，组件内测试跟随组件保存。
